# 公開までの残り手順（実行順）

チャットの履歴が消えても手順が残るよう、ここに正本を置きます。
**順番に意味があります。** 前の手順が終わる前に次へ進むと、やり直しになります。

> ⚠️ このファイルに実店舗名・住所・スタッフ実名・UID・APIキーを書かないこと
> （CLAUDE.md ルール5）。GitHub Pages で全世界に配信されます。

---

## 1. Firebase コンソールでドメインを許可する（手作業）

**これが今の唯一のブロッカーです。**

Authentication → Settings → 承認済みドメイン に、GitHub Pages のドメイン
（`<ユーザー名>.github.io`）を追加します。

診断で分かっていること:

- Authentication は有効（原因ではない）
- **承認済みドメインに Pages のドメインが未登録** ← ログインできない原因
- Firestore は作成済みで、未認証からは正しく拒否されている

同じ画面で **Google プロバイダが有効か**も目で確認してください。
有効かどうかは外部から読めないため、スクリプトでは判定できません。
無効だとログイン時に `auth/operation-not-allowed` が出ます。

## 2. ログインして代表UIDを取得する（手作業）

公開中の画面でログインします。成功したら Authentication → Users に出る
UID（英数字28文字前後）を控えます。**UIDはこのファイルに書かないこと。**

## 3. セットアップスクリプトを実行する

```powershell
.\scripts\yudaya-setup.ps1 -DiagnoseOnly   # まず診断だけ
.\scripts\yudaya-setup.ps1                 # 問題が消えたら本実行
```

本実行で、UIDのルールへの書き込み → Firestore ルールのデプロイ →
コミット＆プッシュ まで通ります。何度実行しても同じ結果になります。

## 4. プルリクエストをマージする

マージすると GitHub Pages に新しいコードが載ります。
**手順5と6はマージ後でないと意味がありません。**

## 5. 履歴の書き換え（破壊的・要確認）

過去のコミットに実店舗名が残っています。マージ後に、全ブランチをまとめて
一度で書き換えます。

**先に書き換えると、開いているPRの履歴と食い違って混乱します。**
必ずマージを済ませてから行ってください。

- 実行スクリプトは**リポジトリの外**に置くこと。
  置換対象として実店舗名を渡すため、リポジトリに入れると
  消したはずの名前が履歴に復活します
- force push を伴います。実行前に必ず確認を取ること
- **GitHubの履歴書き換えは完全な消去ではありません。**
  古いコミットはSHAを知っていれば一定期間読めます。
  完全な削除が必要なら GitHub サポートへの連絡が別途必要です

## 6. 実店舗情報を登録する

`tools/seed-store-config.html` を開き、Firestore の `config/stores`
（代表のみ読取可）に登録します。手順4でコードが公開されていること、
手順1〜3でログインが通ることが前提です。

## 7. 実機確認（手作業）

| 項目 | 見るところ |
|---|---|
| QRの読み取り | 店用スマホのカメラで実際に読めるか。画面の反射・読み取り距離 |

## 任意: スタッフ表示名の登録

Firestore に `config/staff` を作り、`members` 配列を入れます。
未登録ならダミー表記（店長AI / 厨房AI / リーダーAI / じい君）のままです。

```json
{
  "members": [
    { "id": "manager",  "label": "…" },
    { "id": "kitchen",  "label": "…" },
    { "id": "register", "label": "…" },
    { "id": "jiikun",   "label": "…" }
  ]
}
```

`id` は固定です（manager / kitchen / register / jiikun）。
`label` だけが差し替わり、役割と立ち位置はコード側の定義を使います。
